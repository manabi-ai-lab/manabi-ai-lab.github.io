## できなかったこと ❌ と、その理由

### 1. 高画質版そのものの復元・SHA-256照合

**理由：この実行環境から Google Drive にネットワーク接続できません。**

Claude が動いているのはクラウド上の隔離コンテナで、通信は許可リスト方式のプロキシを通ります。
実測した結果：

| 接続先 | 結果 |
| --- | --- |
| `drive.google.com` | ❌ 403（ポリシーで遮断） |
| `drive.usercontent.google.com` | ❌ 到達不可 |
| `docs.google.com` | ❌ 到達不可 |
| `www.googleapis.com` | ⭕ 到達するが、APIキーがないため 403 |
| `github.com` | ⭕ 到達可 |

Drive連携（MCP）経由なら**ファイルの中身は読めます**が、返ってくるのは会話に載る base64 テキストです。
90MiB のパーツ1個で約1億2600万文字になり、8個ぶんは現実的に扱えません。
実際、小さなテキストファイル（150〜1376バイト）はこの方法で取得し、上の検証に使いました。

**つまり「読めるが、大きすぎて運べない」状態**です。回避策として再エンコードで小さくする手はありますが、
それは今回いちばんやってはいけないことなので採用していません。

→ **あっきーのPCで [`RESTORE.md`](RESTORE.md) を実行してください。** 5分の作業です。

### 2. スマホでタップできる高画質MP4のURL

**理由：上の1で元ファイルが手元に来ないため、どこにもアップロードできません。**

CloudFront / S3 の認証情報もこの環境にはありません。

→ **代替案があります。** GitHub Release のアセットURLが、そのまま要件を満たします。

- 再エンコードなし（アップロードしたバイト列がそのまま返る）

- CDN配信

わざわざ CloudFront を立てる必要はありません。詳細は [`RELEASE.md`](RELEASE.md) の「スマホから使えるURL」。

```

=> 403 Resource not accessible by integration
```

同名リポジトリが既に存在しないことは確認済みです（org内は `ganjin` `lab-private`
`manabi-ai-lab.github.io` `BGM` `lab-notes` `-song` の6つ。`manabi-bgm` はありません）。

→ **あっきーが空のPublicリポジトリを1つ作ってください。** [`STATUS.md`](../STATUS.md) に手順があります。

なお、このリポジトリの中身は消えていません。作業内容は
`manabi-ai-lab.github.io` の `claude/manabi-bgm-youtube-release-dkojhi` ブランチの
`manabi-bgm/` 配下に**push済み**です。そこから移すだけで使えます。
